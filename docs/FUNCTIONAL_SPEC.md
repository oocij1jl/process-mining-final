## Evidence-linked rules (deterministic, not LLM)
- Slow transition: top supported mean gap with n and actual metric type; propose investigating handover/queue/resource access. Do not label it confirmed root cause. If n<3 mark low support; no arbitrary thresholds presented as industry standard.
- Rework: count cases containing repeated configured check activity (or adjacent self-loop for generic logs); show denominator and cases. Festival troubleshooting/recheck distinct activity labels are explicitly configured. Suggest pre-check investigation, not guaranteed reduction.
- Workload concentration: rank known resource activity instances/event counts, show coverage and role; no inference of overload without capacity.
- Target breach: emit measured value vs saved target; unsupported metrics N/A. Recommendations linked to evidence IDs and dataset/filter scope. No fixed fabricated benefits.

## Full lifecycle example (illustrative, not measured festival result)
Audience queue finding → choose proposal `Add one staffed gate` → Design save change specification + To-be BPMN reference if available → Model baseline 3 gates, candidate 4, mean wait target 5 min → Monitor recalculates target status against log → Refine computes modeled 3 vs 4 gate wait/throughput → user chooses evaluated scenario → Implementation creates plan to add one gate + one qualified worker, owner/date/status editable. If candidate becomes 5 gates, old result stale; run again and explicitly apply new revision. Monitor shows measured target status and plan progress separately. No physical execution.

## Stage and Equipment deliverables
Same generic Analysis functions, Stage prep KPI + recheck rate + on-time readiness, Equipment request-to-ready + substitution/inspection + performance link. Design proposals from actual log findings, Model targets, Implementation proposal-only plan, Monitor alerts. No fake numeric improvement without simulation. Festival overview compares KPIs and time/role workload, equipment readiness vs linked performance (if keys present). Crowd movement outside entry not tracked. No cross-process DFG.

## UI interaction constraints
Use loading/error/empty/N/A states. All filters scoped. Show raw rows vs discovered event instances. Exports must identify filter and metric type. No dead buttons or invented live feed. If a P1 feature is missing hide or label unavailable. One primary user journey in demo, not six tabs of filler.
